# Iteration Log — 2026-05-27 — Apply 02

## Scope

Implement the deterministic version lifecycle for candidate preparation,
activation, and rollback.

## Completed Slices

1. Updated the reusable memory-version template so scripts can render complete
   manifests from placeholders rather than hard-coded baseline values.
2. Added `scripts/memory-sync/store-utils.mjs` to centralize managed version
   store paths, template rendering, and JSON/text writes.
3. Implemented `scripts/memory-sync/prepare-version-manifest.mjs` to create a
   candidate manifest and dynamic constitution snapshot from explicit Owner
   decisions.
4. Implemented `scripts/memory-sync/activate-version.mjs` to promote a
   candidate, supersede the current active manifest, and update `active.json`.
5. Implemented `scripts/memory-sync/rollback-version.mjs` to restore the
   immediately previous version and mark the reverted manifest as
   `rolled-back`.
6. Added focused Node tests for candidate preparation, activation, and rollback
   lifecycle transitions.

## Validation

- `rtk test node --test scripts/memory-sync/*.test.mjs`

## Outcome

The version store now supports auditable candidate creation, explicit
activation, and safe rollback with executable coverage. The remaining work is to
enforce the same contract in the shared ICM protocol, governed workflows, and
documentation surfaces.
